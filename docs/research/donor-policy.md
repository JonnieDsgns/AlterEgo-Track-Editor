## Recommended policy

1. Existing-track updates: preserve original data and identity by default. No donor replacement unless explicitly requested. For a derived track preserve compatible source resources, remap namespace/IDs and validate new references; layout-dependent data invalidated by edits must be rebuilt or flagged.
2. AC/custom projects: choose one curated BASE PRESET in UI, implemented as a versioned recipe with multiple coherent source families, explicit donor provenance and all-variant coverage. Do not expose arbitrary mix-and-match files as an apparently safe default.
3. Database defaults: separate copy_from_track and copy_slot internally. Prefer same compatible stock track for simplicity unless a tested recipe requires otherwise. Melbourne is a candidate after dataset/schema coverage check; Imola remains development fixture. Track identity is independent from either donor. Never assume all datasets contain chosen base.
4. Environment: select a validated bundle including sky/fog/skylight/postprocess/compass/TOD and all referenced support data. Keep TrackInfo binary/texture pair and its component references together. Authored custom lights are added separately. No random mixing of global/local baked data; local garage/podium probes and spatial bake/DDGI require preservation only when spatially valid, or explicit supported regeneration/replacement. Generic preset means a tested coherent bundle, not invented generic TrackInfo bytes.
5. Functional templates: reuse native component prototypes; regenerate IDs and references, and use authored placement for grid/garages/pit boxes/timing/facilities. Never carry donor positions as finished setup. Match each native variant and vehicle category.
6. Track-specific: own road/terrain, collision, routes, limits, timing, cameras and light placement. Donor geometry/route/collision must not leak into custom export. Physical surface codes follow verified profiles.
7. Vehicle/AI: keep compatible season/category datasets together. Donor response/performance is explicitly provisional for new layouts, cannot be promoted to calibrated all-mode readiness by copying, filename changes or global length scaling. Release-ready V1 requires solving/validating this integration, not hiding it behind donor selection.
8. User controls: Base preset + inherited/authored/unresolved summary; advanced overrides select only compatible complete categories. Show source/version, selected variants and dependent resources; changing donor previews invalidated/rebuilt categories and preserves authored content. Require explicit apply, never silently overwrite authored work.
9. Selection: first filter native build/format, full variant coverage, dependency closure and supported component contracts; then environment characteristics, category and circuit/race characteristics. Closest length or visual resemblance alone is insufficient. No best day/night track ranking is established by current measurements. Candidate environment profiling pool: deeply researched Silverstone/Spa/Suzuka/Bahrain, broaden to Singapore/Abu Dhabi/Las Vegas for actual measured night-capable bundles. These are validation candidates, not certified presets.

## Conclusion

Adopt compatible preset recipes with category-specific provenance, not one universal donor and not unrestricted mixing. Existing tracks retain their own data. Recommend no universal named winner until dependency, dataset/variant and user-run acceptance tests pass. Current unresolved TrackInfo and AI calibration prevent claiming donor policy alone meets the agreed all-mode release requirement.
