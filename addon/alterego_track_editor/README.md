# AlterEgo Track Editor — internal preview 0.2.6

Blender 4.5 minimum. Disable Track Workshop before enabling this add-on: retained operators and properties cannot register alongside the original.

Install the ZIP through Preferences > Add-ons > Install from Disk. Open Workspace creates/reuses the dedicated workspace. AC import retains the Workshop workflow. Asset assignment moves objects while retaining shared geometry and world placement.

Open F1 / Swofty Track imports a stock folder (select an ERP inside it), an addon folder/package, or a raw track package ZIP. Addons may need a base track folder for dependencies. Import retains native identities and every discovered variant, including additional story/previous-season worlds. Variant View changes viewport visibility. Unsupported geometry remains named references; the import report lists preview limitations.

Save Project uses ordinary .blend saving. Packed preview textures survive reopening. Keep original source files available for export. Optional source bookkeeping lives under Advanced Files.

Native export supports moving, rotating and scaling supported existing placements, plus explicit new duplicates of static props (0.2.6). Full Update writes a separate stock-track folder or updated addon/package, preserving original content. Changes-only Swofty packages support stock-track sources only. Outputs must be outside source and game installation. Unsupported edits are rejected. Placement changes do not rebuild separate collision data.

The material library offers thumbnail selection, local .blend pack loading, explicit curation and independent copies for objects/selected faces. Native shaders are approximated. Material edits do not yet export native materials/textures. No game-derived pack is bundled.

The facility library curates selected actual geometry and places shared references at the cursor, with bounds and possible-overlap warnings. These are placement references; native insertion remains in development.

This is not V1. New geometry, terrain, collision, native material export, facility insertion, race systems and complete all-mode game validation remain unfinished. BC7 previews need an available Pillow decoder or are reported unsupported. No game assets, executables or runtime backend are bundled. No game loading/gameplay has been verified. See repository docs/NATIVE_EDITING.md for tests and limits.

0.2.1 adds Export Selected Geometry Test under Advanced Files for an imported native mesh. It writes evaluated local geometry to a separate ERP copy using the existing native template/material binding. Only supported single-LOD, single-submesh static families are accepted; required UV pairs and colours must be explicit. It does not mount new objects, update placement/collision, or generate a complete track. Main Native Update still rejects mesh edits. See repository docs/research/static-writer.md.

0.2.2: select an imported native mesh > Project Settings > Advanced Files > Load Geometry LODs. This loads actual native detail levels into separate editing meshes, preserving all UV pairs and colours. Preview buttons show one level at a time; loading again reuses edits. Export Selected Geometry Test includes every companion LOD, including hidden levels, and supports multiple existing material submeshes. Missing LODs or mismatched native material assignments are rejected. The original placed object remains unchanged. Output retains the existing resource family; collision, new asset identities and full track/Swofty integration remain unfinished. Empty LODs, split draws and multi-archive families are currently unsupported. See repository docs/research/static-writer.md for exact checks and limits.

0.2.3: Export Independent Asset writes a new folder (the chosen ERP filename without its extension) containing asset.erp and asset.json. This contains renamed LOD resources and native material bindings, with external material dependencies listed. Names may receive a deterministic suffix to keep opaque record addresses unchanged. It does not insert a world object, export collision, bundle all shaders/textures or create a track package.

0.2.4: Export Independent Asset can bundle supported native materials, texture views/surfaces and external mip files. Shared native shaders remain explicit externals. Alternatively, Write a native track copy embeds edited geometry and retargets the existing selected model/context in a separate native folder copy. This retains original material dependencies, collision and race data; addon package targeting and new object insertion are unfinished. See docs/research/dependency-packing.md.

0.2.5: the Collision panel loads native cells around the 3D cursor. Assign Physics Code edits selected faces (Edit mode) or selected cells (Object mode). Export Collision Surface Update writes a separate copy while retaining geometry/search data. Shared-resource edits apply to its original references; other authoring workflows are not combined. Moved/modified native geometry is rejected. Authored meshes with Collision enabled and an explicit code can export a Legacy Collision Test (.jpak, version0x20002), which is not a verified F1 25 replacement. Native0x20004 geometry generation and visual-terrain writing remain unfinished. See docs/research/collision.md.

0.2.6: select imported native static props and choose Duplicate as New Placement. The copy shares the source model and stays in the same layer/variants; move it, then Export Updated Native Track. Swofty Update Addon now defaults to Composable Edits (launcher patch-pkg set/clone edits that combine with other addons); Whole Layers keeps full-layer replacement. Functional objects (grid, garages, cameras, audio, lights, triggers and similar) cannot be duplicated, and plain Blender copies are rejected at export. New placements are visual only: no collision, precomputed visibility or lightmap data is generated. The export report text lists generated names/uniqueids. See docs/research/native-insertion.md.
